# ADR-0034: Deploys use Helm 4; Helm 3 stays pinned for manual checks

## Status

Accepted.

## Date

2026-11-20

## Context

Helm 4 is the current line. The chart testing tools (ct, helm-unittest, kubeconform) needed to be checked against it
before the deploys could depend on it, and adopters may still run Helm 3.

## Decision

CI and the deploy scripts install the pinned, checksum-verified Helm 4 (`helm4` in
[`mise.toml`](../../mise.toml), locked in `mise.lock`) first on `PATH`, so a runner's own Helm is never used, and deploy with
`--rollback-on-failure` (Helm 4's name for `--atomic`). Helm 3 (`helm3`) stays pinned and installable
(`scripts/tools.sh install helm3`) for a manual render on 3.x. The chart was rendered on Helm 3 once by hand; nothing
in CI re-proves it.

## Consequences

- Good: one known Helm everywhere; Renovate moves it with its checksum.
- Bad: two Helm pins to keep; an adopter on Helm 3 uses `--atomic` instead.
- Bad: a chart change that breaks Helm 3 is not caught in CI; an adopter on Helm 3 renders it once themselves.

## Alternatives considered

- Stay on Helm 3: rejected, it is the older line.
